# CodeLens 正式版封装分工安排

产品统一命名为 CodeLens。首发暂按 Windows x64、Electron 和单个安装包规划。下表为建议排期，以启动当天为 D1；Codex 负责实现、构建和发布，豆包负责独立复核，用户转交命令与回执。所有实施任务待认领。

| 批次 / 时间 | 负责人 | 依赖与第一步 | 可验收产物与放行条件 |
|---|---|---|---|
| A · D1 发布基线 | Codex | 核对 main 与发布工作树的版本差异，从 README 的静态发布命令生成清单 | 记录源码提交、77 个主题清单和功能范围；历史 C 实验另列集成条件，明确本次是否随包交付 |
| B · D2–3 桌面入口 | Codex | A 后，从已校验的静态产物加载首页 | 可启动的 CodeLens 桌面程序；断网可打开冒泡排序、修改输入、生成步骤、回放；退出后无残留服务 |
| C · D2–3 本地运行依赖 | Codex；豆包复核依赖清单 | 与 B 并行；对照旧 C 实验说明核对 Python、工作进程与运行限制 | 提交依赖和验证记录；若 A 确认集成，交付本地服务，验证受限访问、超时终止与退出清理，接入同一应用 |
| D · D4 安装包 | Codex | B 与本次范围内的 C 通过后，用 electron-builder 打包 | 生成带版本号的 Windows x64 安装程序；记录构建命令、版本、签名状态与 SHA-256 |
| E · D5 独立验收 | 豆包；Codex 提供冻结包与实测证据 | 在干净 Windows x64 环境安装 D 的冻结包 | 断网检查 77 个主题入口，抽测排序、图和树的输入、回放与时间轴；验证所有随包功能及卸载。按安装包哈希记录结果，修复后复测 |
| F · D6 下载交付 | Codex | E 通过并取得发布权限后，上传同一安装包到 GitHub Releases | 发布说明列明系统要求、功能与校验值；README 提供下载入口；从入口重新下载安装并核对哈希 |

现有证据为 README 的静态构建与校验流程、旧 C 实验说明，以及执行计划中的发布工作树记录。静态清单排除了历史后端，不能作为后端打包成功的证据。上次推送缺少非交互凭据，发布负责人应在 D1 核对权限，本地构建和测试可继续。

工具安排：Electron 与 electron-builder 是项目构建依赖。上述任务无需额外 Codex 插件；构建工具、干净 Windows 环境及发布权限均由对应负责人接手时核实。总调度维护执行计划，测试负责人只读复核候选包。若 C 集成或安装验收出现缺口，顺延发布日期。
